Install Ember

Your own chat server, maintained by NYLLON. Stable release {{VERSION}}.

Before you begin

Use a fresh Ubuntu 24.04 or Debian 13 server with an amd64 or arm64 CPU, at least 2 GB RAM, 10 GB free disk, root access, and inbound TCP ports 80 and 443 open. Use an interactive terminal. Existing working Docker installations are reused. Conflicting packages or occupied ports must be resolved first.

Create a DNS A record such as chat.example.com pointing to the server’s public IPv4 address. If you publish AAAA, IPv6 must reach the same server. Use DNS-only mode when using Cloudflare DNS. Wait for the records to resolve before installing. Ember obtains and renews HTTPS certificates itself.

Install

Connect to the server as root, then run:

curl -fsSL https://get.nyllon.com/ember | sh --

The installer asks for your hostname, installs Docker from its official signed repository when needed, verifies the NYLLON installer bundle, and starts a digest-pinned image. It reports success only after HTTPS works. Open the private setup link it prints to create the first administrator in your browser. Keep this link private. Until setup is complete, root can recover it with emberctl setup-link.

Operate and update

emberctl status
emberctl logs
emberctl restart
emberctl update
emberctl update 1.2.3
emberctl reset-password admin@example.com

Updates are manual. Only tested NYLLON stable releases are installed; changes from upstream Campfire pass through ordinary review. Password recovery prompts privately and never takes a password on the command line.

Back up and recover

emberctl backup
emberctl restore BACKUP_ID --accept-data-loss

Backup briefly stops Ember to capture a consistent copy of all storage, uploads, certificates, configuration, secrets, and release metadata. Backups are root-only and stored outside live storage in /var/lib/ember/backups/BACKUP_ID. Copy the complete backup directory, including its snapshot and checksum metadata, off the server over an encrypted connection, for example with scp, and keep them encrypted at rest. Local backups do not protect against losing the server.

Updates download and validate the new image before stopping Ember and create a complete backup before starting it. A failure before the new version starts can resume the old version. Once the new version touches live data, recovery requires an explicit restore. Restoring discards data written since that backup; the failure message names the backup and restore command. Do not remove the recovery journal before resolving it.

Troubleshooting

Check emberctl status and emberctl logs. For HTTPS failures, verify DNS, any AAAA record, ports 80/443, and the server clock. Registry and download failures leave the current installation intact before cutover. Rerunning the installer preserves managed configuration, data, and secrets. It refuses unmanaged Campfire or ONCE installations; migration is a separate project.

Configuration is in /etc/ember; persistent data is in /var/lib/ember/storage. Do not edit or delete these during recovery.
